# 把旧问题与迁移问题分开

先等价是为了建立可追溯的参照，不代表认可原模型的全部物理或规则。兼容模式保留旧行为，修复由配置选择。缺陷清单中的来源陈述也要验证：不能因为教程写了“未使用”，就把 XML 属性名误当成参数引用。

| 原问题 | 实际复现方法 | 修复或处置范围 |
|---|---|---|
| A 两圆中心完全重合不分离 | 把机器人 2 放到 1 的坐标，调用原数值迁移函数，间距仍为 0 | 非 ACompat 碰撞求解使用确定方向分离 |
| A 单轮两两分离仍重叠 | 三台放在 x=0,0.1,0.2，y=0；至少一对距离仍小于 0.30 m | 迭代投影，并报告残差；不使用保守停步过滤 |
| A 重开站位简化、无对手距离 | 越右端线、最后触球队 1，球被放在 (3.5,1.5)；边线球 y=2.75 | ACompat 保留；参考配置明确选择位置和距离；不宣称完整 RoboCup 裁判 |
| A 控球率实际为最后触球时间 | 找到球与所有机器人分离但 touchTime 仍增加的采样 | 保留兼容数据列，显示和手册明确改称最后触球时间 |
| B 乌龙按最后持球者计分 | 从 SLX 提取实际赋值语句执行，蓝队最后持球时蓝队分数增加，和球门方向无关 | 新裁判按进球端确定受益队；不继承 B 的 Ball Simulation |
| B 无人持球却保留编号 1 | XML 初值为 1，执行 robotIdx=0 的原条件片段，仍引用 1 | 新裁判 lastTouch=0，球门方向决定进球；未触球重开采用显式假设 |
| B 两参数未被使用 | 扫描足球模型与库 XML 的参数**值**和 MATLAB 源码；属性名不计为使用 | 不继承 wheelRadius；新 FOV 参数有输入影响测试 |
| B 多次 Randomize 累加 | 同种子连续两次执行原脚本，第二次偏移是一次的两倍 | 新实验从固定初态重新扰动，重复种子得到相同初态 |

B 的两个计分问题是**原状态动作片段的可执行复现**，不是整个旧 B 模型的集成验证。提取证据在 `evidence/3/b-source-extract.json`，源码片段在 `baseline/BScoringOracle.m`。本版没有沿用这些状态。未使用参数是依赖审计，不把它冒充运行完整 B 的结论。

最初的参数审计把 `<P Name="robotDetectorFOV">pi/3</P>` 的属性名也匹配进去，产生假阳性。修正后的审计只检查表达式文本。该可视化实例实际设置 hasRobotDetector=off，视场字段为常量 pi/3；它没有读取脚本变量 robotDetectorFOV。失败结果和修正结果都保留。

碰撞修复属于几何约束算法，不是人形接触动力学。迭代次数上限、残差容差、活动机器人集合、场地外缓冲边界都要单独说明。不能仅以“无 NaN”证明无重叠，更不能把没有停步过滤写成不会受阻。600 s 报告分别列出重叠采样、最大穿透、越线采样和有平移请求但未移动的比例。
