# 两队策略隔离的独立核对

蓝队是 1–4 号，红队是 5–8 号。此次四场端点及下述人工故障用于校验路由；统计红、蓝单队效应的 80 场比赛另有逐场回执，未带入故障注入。

- 协调器入口 `tdp.teamPolicyPlans` 给选择自动的队传原八参数接口（含健康包），给默认队传原七参数接口及该队已有的显式恢复信号。共用的扩展队记忆并不会自动赋予默认队严格编号门。测试同时令两名前锋定位暂失，再等到 1.40 s 只向默认队提供显式恢复，用两种队色方向和两个周期核对各自的实际接管解除时刻。
- `V1AuthorizeRequests` 按机器人全场编号选本队的动作保护门。测试把两队中场都放在交还编号 17 的边界，均给出新请求 Kick(18)，对照默认与自动两种授权契约。另在隔离副本中故意删去这一处队色判断，红、蓝两种方向的错授权均被同一测试识别（同级 `isolation-mutation-01/`）。
- `Actuator2D` 用 `obs.selfIndex` 决定错号 Stop 是否撤销设备正在准备的动作。`RecoveryFeedback2D` 按设备编号决定是否冻结其健康包与反馈；`RecoveryPlant2D` 保留已离场且没有在途动作的默认设备的原空反馈返回行为。真实模型测试给两台前锋执行器同时置入 17，然后在比赛运行中给出另外的 Stop 编号，同时丢弃第一拍的实验回传。默认设备当拍回 Failed(17)，实验设备先回之前的空反馈，恢复通信后回与 Stop 同编号的 Rejected，17 仍留在实验设备。这里观察的是执行器返回和活动编号，不能替代实际出球事件。
- 端点使用相同新模型，掩码分别为全 false、全 true。50 ms/seed 5 与 40 ms/seed 11 的原 600 s 比赛都存在真实红队接管；默认版本接管持续，自动端在这两场分别观察到 2、1 次红队交还。以逐行、小端 IEEE 754 双精度字节计算物理 98 列、战术 171 列，以及自动端的 53 列诊断 SHA-256，对照仓库中上一轮正式归档的 `artifact.json`。只需小型哈希回执即可在新 clone 重做，无需复制外部 MAT。
