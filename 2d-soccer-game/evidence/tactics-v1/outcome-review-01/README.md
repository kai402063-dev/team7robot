# 为什么这场 109 次射门打成了 0∶0

正式二维比赛使用 50 ms 控制周期、种子 1，运行 600 s。蓝方向 +x 进攻，红方向 −x 进攻。独立脚本直接读取保留的物理状态和战术记录，比较 12,000 行 × 98 列、12,000 行 × 171 列的浮点数组。两组数组均与预检逐项相同，完整 SHA-256 见 [receipt.json](receipt.json)。以下结论只针对这一场。

**蓝队的球确实踢了出去，而且很快就碰到红方后卫。** 裁判按前锋或中场实际完成速度至少 1.8 m/s 的踢球计射门。蓝方前锋有 21 次、中场有 88 次，起脚时球距球门中心的中位距离为 2.379 m。109 次射门的第一次对方接触全部来自红方后卫（全局 6 号）。从起脚到接触，中位用时 0.20 s、最长 0.45 s；从出脚前球位到首次接触后球位的直线位移中位数为 0.366 m。接触判定要求球与机器人中心距等于两者半径之和 0.22 m（容差 10⁻⁹ m），并核对最后触球队。108 次出脚与接触发生在不同采样拍，按上一拍球速和本拍后卫速度重算接触冲量，接触后球速度与轨迹的最大误差为 3.15×10⁻¹⁵ m/s 以下。另一次出脚当拍即碰到对方，轨迹只保存了当拍处理完接触的球速。[射门计数](../../../environment/Plant2D.m) · [碰撞计算](../../../environment/Contact2D.m)

**多数出球方向和距离本来足以把球送进门框。** 对上述 108 次可读到未受碰撞影响的初始出球方向的射门，保留该方向、实际出脚速度和滚动减速，每 50 ms 推进一步，直到停球或首次出界。按本场“整个球越线且在两柱之间”判定，92 次在这项空场计算中会进球。比赛中的红方后卫有明确的站位依据：V1 把其站位目标放在本方球门中心指向球的射线上，蓝方持球队员又把射门目标设在球门中心。这与 109 次早期接触的分布一致。这个几何推算只改变单次出球之后的条件，不能推断整队换战术、删除后卫或更换种子后的比分。[站位与射门选择](../../../algorithms/+tdp/v1TeamPlans.m) · [滚动](../../../algorithms/+tdp/ballModel.m) · [进球判断](../../../environment/Referee2D.m)

**红方进入了进攻状态，却没有把球推进到射门区域。** 两队均从 Attack 开始。红方在第一个样本 0.05 s 至 9.00 s 处于 Attack，共 180 拍，随后累计防守 586.25 s、停赛 4.75 s。开场前锋实际轻踢 4 次，之后防守阶段中场轻踢 2 次，6 次速度均为 0.6 m/s。球的最小 x 为 −0.059 m，始终未越过红方进攻侧的切换线 −0.15 m。开场进入 Attack 和完成轻踢都有迹可查；这场的球位也解释了红方为何未能在对方门前形成射门机会。[初值](../../../algorithms/+tdp/v1TeamMemory.m) · [攻防切换](../../../algorithms/+tdp/v1TeamPlans.m)

**复算。** 在工作树根目录运行以下只读命令。依赖 Python、NumPy 和 SciPy。若 MAT 文件已另外归档，追加 `--mats 预检.mat 正式.mat` 提供原文件，脚本首先核对两份 MAT 文件各自的 SHA-256，再读取数组。

```sh
python3 evidence/tactics-v1/outcome-review-01/inspect_game.py \
  evidence/tactics-v1/matrix-longcheck-01/dt50-seed01/receipt.json \
  build/v1-clean-01/evidence/tactics-v1/matrix-final-01/matches/dt50-seed01/receipt.json
```
