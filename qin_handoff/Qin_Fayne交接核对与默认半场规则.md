## 3. 默认半场规则 H1

本次继续采用上一版默认值，保持历史结果可比较。默认定义如下：

| 项目 | 默认约定 |
|---|---|
| 坐标 | 使用现有项目坐标：球场中心为原点，x 沿长边；蓝攻 +x、红攻 −x。坐标方向是代码约定，不是 PDF 指定 |
| 分类对象 | 足球球心，不是机器人位置，也不是最后触球队 |
| 左半场 | `x < -1e-9 m` |
| 中线 | `abs(x) <= 1e-9 m`，独立计时，不归蓝或红、不平分 |
| 右半场 | `x > 1e-9 m` |
| 计时 | 每个满足条件的样本累计 dt，使用仿真秒数，不使用电脑运行耗时 |
| 可分析样本 | `running=true`，且不属于新发生的重开转换拍或已记录的整球出界样本 |
| 暂停 | 单独统计，从半场比例分母中排除 |
| 重开转换拍 | `pauseUntil(k)` 比前一拍增加；球可能已重置，单列，不强行分半场 |
| 出界 | 暂用现有裁判模型：整球过线，即球心越过 `L/2+ballR` 或 `W/2+ballR`；这是代码一致性约定，不是从课程 PDF 推导的统计要求 |
| 球门附近 | 未触发出界/进球重置时按 x 分类；进球用比分增量识别，不靠重置后的球位置 |
| 跨中线 | 物理停留指标按本拍结束位置分类，不凭两行数据插值出更细事件时刻 |
| 比例分母 | 左 + 中线 + 右三类时间。跨比赛先累加秒数，再除以总分母 |

1e−9 m 只是浮点容差；不是实际球场线宽，也不是协调器的战术带宽。满足此定义时，左 + 中线 + 右 + 暂停 + 重开转换 + 出界 = 已记录比赛时间。

统计不应为了“左右比例加起来等于 100%”而隐去中线时间。若需要仅比较左右的条件比例，可另算 `left/(left+right)`，但必须换名称并注明排除了中线。

## 4. 一拍对齐：必须分开两类问题

Fayne 的行对齐提醒与当前模型源码一致：`tactics(k,:)` 使用的是上一拍世界状态；`trace(k,:)` 是本拍执行、碰撞和裁判后的状态。

因此本次保留并区分：

1. `halfSeconds`：描述实际记录到的球位置，使用 `trace(k)`。它回答“球的离散采样停留时间”，保持上一版结果不变。
2. `decisionHalfSeconds`：描述作出决策时可见的世界位置，使用 `trace(k-1)`，按左/中线/右输出。它回答“做这个决策时球在哪一半场”。

首拍没有保存 pre-state，而且模型允许覆盖初始世界，不能凭空假定它必定在中线。该拍记入 `decisionHalfUnknownSeconds`；已知但出界的前状态另计 `decisionHalfOutsideSeconds`。其余已知半场时间 + unknown + outside = running 时间。

决策半场不套用本拍结束后的重置过滤，否则会拿后发生的裁判结果删除之前合法发生的决策。暂停结束后的第一拍可以合法看到重开点。由于这两类问题和分母不同，两个半场指标不应要求数值完全相等。

同理，当前控球估计仍是本拍结束真值的几何代理；不能直接用它证明协调器在决策时“已持球却做错了动作”。因果分析需读取前一拍几何状态。

## 5. 本次新增的交接指标

### 防守阶段无人追球比例

```text
D_team = dt × count(running & phase_team == Defend)
N_team = dt × count(running & phase_team == Defend & chaser_team == 0)
ratio_team = N_team / D_team
```

这里按交接建议使用 `phase`，不是 `basePhase`；Fallback 即使保留 Defend 基础状态，也不混入此指标。D=0 时返回 NaN，JSON 中为 null，而不是零。跨比赛必须使用 `sum(N)/sum(D)`，不能把每场比例直接平均。保留 numerator 和 denominator，输出在 `defend_seconds.csv`。

本次重新分析旧 V1 的 600 秒基线：

| 队伍 | Defend 秒数 | Defend 且无追球者秒数 | 比例 |
|---|---:|---:|---:|
| 蓝 | 0.00 | 0.00 | 不适用 |
| 红 | 586.25 | 551.65 | 94.10% |

这与上一版红队“全部可分析时间中的无追球授权 551.40 秒”不是同一个口径。新指标使用 running 和 Defend，不排除重开转换拍；旧指标使用排除转换拍后的 E。差异 0.25 秒有明确来源，不是数字修正。

### 追球与静止

保留 `chasingState`（Approach/Align）以兼容旧表，新增 `chasingIncludingKickSeconds`：running、机器人可用、持有追球授权，且处于 Approach/Align/Kick。该字段包含踢球阶段，因此不把它称为“实际移动秒数”；实际移动仍需看速度。

保留 `idleState` 表示 Stateflow Idle；新增 `stationarySeconds`：running、机器人可用，实际平移速度 ≤0.02 m/s。再按有效请求分为 Stop、Goto、其他三类，三者合计等于静止总时间。

**Goto 且静止不一定是“已经到位保持”。** 也可能正在转身、碰撞受阻或其他原因。没有进一步距离/朝向条件或接触证据时，只标 `effectiveGoto`；不伪造“到位”判断。这里测的是平移静止，不排除原地旋转。

V1.2 的 DF 追球无需增加日志列；当前统计器的授权映射已支持队内编号，不把 DF 当成非法数据。是否 GK 被错误授权由战术不变量检查判断。每份指标现在也保存 `policyIds`；没有 v12Policy 时为空，不擅自标成 neutral。

## 6. 如何在 Yu 对接后修改

统计函数现支持可选参数 `centreBandMetres`。不传参数仍是 1e−9 m 默认值。

```matlab
cd('C:/Users/16672/Desktop/code/team7robot-fayne-bahaviours-tactics/2d-soccer-game');

% 若 Yu 决定采用宽度 ±0.15m 的独立中立带：
out2 = [out '-band'];
qinAnalyzeRecording(f,out2,struct('centreBandMetres',0.15));
```

**±0.15 m 独立中立带不等于协调器的滞回规则。** 协调器可能在带内保留上一基础攻防状态，而此选项把带内样本都单独计为 centre。若 Yu 要求“进入带后保留上一半场”，应另实现有状态的分类器并测试，不能只改一个数值后声称两者一致。

当前可直接配置的是中线带宽；暂停、转换拍、出界判据属于已测试的明确代码约定。若团队调整这些，应升级指标版本、补充边界测试、重新分析保存的日志，并保留旧版结果。无需因此改变机器人战术或重新运行原比赛。
